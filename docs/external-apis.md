# External services and outages

The fallback depends on which service is unavailable. Manual university entry, calendar downloads and manual decks all still need a working Supabase connection to load or save student data.

| Service | What UniArena sends and when | What the student can do during an outage |
| --- | --- | --- |
| ROR university directory | The profile search sends the typed university name after at least two characters and a short typing pause. Choosing a previously unknown typed name can trigger a server lookup. | Choose a university already known to UniArena or select **Use “…”** to keep the typed name. The browser stops waiting after eight seconds. Successful lookups, including empty results, are reused for ten minutes, up to 128 queries per cache. Failed requests can be retried immediately. |
| Google Calendar | After explicit consent from a registered Google test account, UniArena sends session titles, course details, dates, times and durations to the primary calendar. It stores the event IDs for the plan in Supabase. The access token is short-lived. | Open the saved Study Plan, choose **Calendar file** and import the downloaded `.ics` file. This works without signing in to Google. For an interrupted direct sync, retry using the **same Google account**. Each new plan slot has a stable Google event ID. Existing tracked events are updated in place, including entries synced before this change. A later retry with the same plan can recover a successful creation whose reply was lost. |
| Supabase Auth, PostgreSQL, Storage and Edge Functions | UniArena authenticates the student, reads and writes private profiles, decks, messages, plans and multiplayer state, retrieves profile images and calls the AI functions under the student's identity. Shared features fetch current state when opened, refreshed or polled. | A full outage blocks sign-in, fetching fresh shared data and saving changes. A screen may still show previously loaded content. There is no offline save queue. After service returns, sign in again if prompted and reopen the relevant screen to check whether a pending action was saved before retrying it. A Storage-only outage can affect pictures while sign-in and the database remain available. |
| Resend via Supabase Auth email | Signup confirmation and password recovery use transactional email. Supabase submits the recipient address and the verification or reset email to its configured SMTP provider. | With email delivery down, new students must wait to verify and anyone needing a reset must wait for a working link. Already verified students who know their passwords can still sign in if Supabase Auth is healthy. Check inbox and spam. After recovery, request a fresh reset email if needed. A successful request in the app does not confirm inbox delivery. |
| Requesty AI via Supabase Edge Functions | Explicit generation sends selected source material to the configured model. Optional Anki image reading sends the selected card images. Generation batches contain at most ten source cards, with up to 100 cards per generation. | A failed generation shows an error and preserves the source cards. No partial AI draft is published or saved. Retry later or create questions manually under **Decks**. If image reading fails, skip the affected images and continue with usable text cards. Existing decks remain usable when Supabase is healthy. |

## Credentials, limits and provider terms

- **ROR** is free and its directory metadata is CC0. The application needs no secret to search. The browser cache lives with the search field and the server caches public directory results in memory. [ROR terms](https://ror.org/about/terms/) · [Client identification and rate limits](https://ror.readme.io/docs/client-id)
- **Google Calendar** uses the OAuth client ID and secret configured on the Streamlit server. Quotas apply per project and per user. Calendar file downloads consume no Google quota. The time limit for an individual HTTP request is 15 seconds. Only import a downloaded file once or check the destination calendar first if a direct sync partly succeeded. [Calendar quotas](https://developers.google.com/workspace/calendar/api/guides/quota) · [Event IDs and retries](https://developers.google.com/workspace/calendar/api/guides/create-events) · [Google API user data policy](https://developers.google.com/terms/api-services-user-data-policy)
- **Supabase** uses the configured project URL and publishable key together with each student's session and database access rules. Check the project dashboard for current database, Storage, Auth and function usage. [Supabase usage and billing](https://supabase.com/docs/guides/platform/billing-on-supabase)
- **Resend** SMTP credentials belong in Supabase Auth settings. Resend Free lists 100 transactional emails per day and 3,000 per month. Supabase Auth can also rate-limit requests. The team can check Auth logs and Resend delivery logs to distinguish a rejected request from a delivery delay. [Resend pricing](https://resend.com/pricing) · [Auth rate limits](https://supabase.com/docs/guides/auth/rate-limits)
- **Requesty** uses the server-side Supabase function secret `REQUESTY_API_KEY`. Cost and data handling depend on the configured model and account. Check the model's retention terms before submitting private study material, and check workspace credits before a demo. The functions set a 45-second deadline per provider attempt and retry eligible failures once. [Requesty pricing](https://www.requesty.ai/pricing) · [Requesty terms](https://www.requesty.ai/terms)

## AI settings for the class demo

On 21 November 2026 both deployed Supabase functions, `generate-questions` and `extract-image-text`, used the default model `openai/gpt-4o-mini`. The production project listed `REQUESTY_API_KEY` and neither model override. This was checked in the Supabase dashboard without sending student material or making a model request.

Requesty's free allowance applies to eligible models. The Supabase configuration does not show the Requesty account balance, effective rate limits or spending cap. The teammate who owns the Requesty workspace can confirm the allowance for this model, remaining credits and the cap on the UniArena key before a live generation demo. If the team cannot verify them, use an already saved draft to demonstrate review and publishing without a provider call. One 100-card generation starts with ten batches and retries or quality rewrites can use more requests.

## Reproduce the checks

Run `uv run pytest -q` for the Python suite and `node --test tests/university_picker.mjs` with Node 22+ for the browser picker logic. The Calendar regression test simulates a saved event followed by a lost response. The picker test advances a simulated clock through cache expiry and a stalled search, selects the typed name, and checks that a later lookup can succeed. Both use fake services. The provider-side AI tests can be run separately with `deno test --deny-net supabase/functions`.
