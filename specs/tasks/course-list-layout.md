# Course list on Decks

Parent topic: [Appearance and navigation](../appearance-and-navigation.md).

## Why

Students need a quick overview of every course they selected, without switching a course picker before they can choose a learning path.

## What

The Decks page keeps its existing creation area at the top. Beneath it, it presents the student's courses as a vertical desktop-friendly list. Each course card has an initials tile, a concise availability status and a deck-count pill. Every course has its own **Search [course] Study decks** field. It searches deck names only within that course, independently of searches in the other course cards. Matching results appear directly below the active course search rather than inside its dropdown. Each row shows the real count of available Study decks. Battle decks are not shown on this screen; Battle matchmaking starts only from **Play → Battle Mode**. Without an active search, clicking a course row's **View all study decks** dropdown expands that course's available Study decks. It provides **Recently added** (the default, ordered by publication time) and **A–Z** sorting. Every row shows its icon, name, question count and a **Study** action on the right. Choosing it opens Play → Study Mode → Study alone with that specific deck preselected. If the deck belongs to another student, the action first saves the existing private Study copy and then preselects that copy. A course without Study decks, or without a matching search result, says so in the relevant course section. The course card does not add a shortcut for creating the first deck.

## Out of scope

Changing deck visibility, publication, learning progress, Battle matching, or course membership.

## Done when

1. Every course in the signed-in profile appears exactly once as a vertically stacked row.
2. A row displays only counts derived from available Study decks. Every listed Study deck opens Study alone with that deck selected; Battle matchmaking remains available only from Play.
3. Every course search narrows only that course's Study-deck rows whose names match and shows those results directly below that course's search field, without persisting data or changing the available-deck count.
4. The original creation controls appear once, above the course list, in light and dark themes.
5. Reloading preserves the profile's courses and deck data; no new course-list data is persisted.
6. Each course row has a dropdown that lists exactly that course's available Study decks, with the direct Study action on every deck.
7. Battle Mode decks do not appear anywhere on the Decks page.
8. An expanded course list can be sorted by newest publication or deck name without changing the available data.
